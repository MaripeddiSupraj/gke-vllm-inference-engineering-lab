## How the request travels (important learning)

1. Operator forwards local port 8080 to Kubernetes ClusterIP Service `fastapi`; this is local debugging access, not an internet-facing LoadBalancer.
2. Service selects the FastAPI Pod on the CPU node. FastAPI validates `X-API-Key` against the key injected from Kubernetes Secret.
3. FastAPI reads `VLLM_URL` from its Pod environment and issues an OpenAI-compatible HTTP POST with `model`, `messages`, `temperature`, `max_tokens`.
4. VPC peering routes the request to GPU VM private IP; temporary proxy accepts traffic on `10.148.0.2:8000` and forwards to vLLM bound to VM localhost.
5. vLLM runs model prefill/decode on the NVIDIA L4, returns text and token usage; FastAPI transforms the response and returns it to the client.
6. The Kubernetes scheduler placed FastAPI on a CPU node. vLLM's internal request scheduler is a separate system. **No Kubernetes GPU scheduling was tested yet.**

## Important drift and limitations

- `gke-l4/k8s/20-fastapi.yaml` still contains an image placeholder and `VLLM_URL=http://vllm:8000/...`; the working cluster was configured imperatively with `kubectl set image` and `kubectl set env`. A future manifest apply may revert these changes. Move image and backend URL into environment-specific overlays or Helm values, not a hard-coded ephemeral private IP in shared defaults.
- Peering, GPU VM proxy, firewall rule and Artifact Registry IAM were applied outside Terraform; reconcile and choose ownership before the next repeatable deployment. Do not automatically manage/delete existing GPU VM resources.
- The current `/health` only confirms FastAPI process health; it does not prove vLLM is healthy. Add a separate dependency readiness check with appropriate failure semantics.
- The vLLM proxy uses plain HTTP without backend authentication; peering is not encryption. Restrict ingress, validate firewall rules, and implement workload authentication/TLS for production.
- Current image was built for AMD64 only. Consider a pinned multi-platform CI build with digest verification.
- Prometheus/Grafana/DCGM container existence is not proof of successful scraping or useful dashboards.
- GPU VM has a public IP; private backend access must never rely on an unrestricted public firewall rule.
- Cloud Billing budgets are alerts, not spending caps. GKE and GPU VM accrue charges while running.
